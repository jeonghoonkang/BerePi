# Python Jev Creator와 Runner

Python Jev Creator는 기존 Python 코드의 선택한 조건에 TypeSafe AI의 Jev 호출을 추가합니다. Python Jev Runner는 이렇게 생성된 응용 서비스의 기능을 대화로 알아보고 실행하는 데스크톱 앱으로 설계되어 있습니다.

| 응용 | 역할 | 현재 상태 |
| --- | --- | --- |
| [Python Jev Creator](python_jev_creator/README.md) | Python 조건문 분석, 판단 후보 제안, Jev 호출 코드 생성 | 구현 완료 |
| [Python Jev Runner](python_jev_runner/README.md) | 서비스 기능 안내, 입력값 수집, 대화형 실행과 결과 표시 | 설계 단계 |

```mermaid
flowchart LR
    A["기존 Python 코드"] --> B["Creator<br/>조건 분석 · 적용 지점 선택"]
    B --> C["Jev 응용 프로젝트"]
    C --> D["서비스 명세와 실행 어댑터 추가"]
    D --> E["Runner · 설계 단계<br/>기능 안내 · 입력 수집 · 실행"]
```

## Creator 사용 방법

Python 3.9 이상과 Tkinter가 필요합니다. Windows에서는 저장소 루트에서 실행합니다.

```powershell
py -3.9 apps/agentai/jev/python_jev_creator/main.py
```

1. Python 파일이나 프로젝트 폴더를 선택하고 **분석**을 누릅니다.
2. 후보의 위치, 조건식, 전송 변수를 확인합니다. 적용할 조건을 선택하고 판단 질문을 검토·편집합니다.
3. **선택한 지점에 Jev 코드 생성**을 누릅니다. 원본과 같은 상위 폴더에 `기존폴더명jev`가 생성됩니다. 개별 파일을 선택하면 해당 파일만 복사됩니다.

코드 분석과 생성은 로컬에서 수행합니다. 생성된 응용 프로그램을 실행할 때 `TYPESAFE_API_KEY`를 설정하면 선택한 조건에 쓰이는 변수 값과 질문이 Jev로 전송됩니다. 키가 없거나 API 호출이 실패하거나 판단이 불확실하면 기존 조건 결과를 사용합니다.

후보 탐지는 정적 분석으로 이루어지며, 모의 API 응답으로 생성과 오류 처리를 검증했습니다. 실제 API 연동과 업무별 판단 정확도는 검증이 필요합니다. 업무의 의미를 판단하는 조건부터 검토하고, 수치 비교나 권한 확인에는 기존 Python 로직을 유지하는 편이 적합합니다.

## Runner 설계

Runner는 말풍선 GUI에서 **기능 안내 → 입력 수집 → 실행 요청 → 진행·결과 표시**를 지원하도록 설계했습니다. 예를 들어 사진 보관 서비스의 기능을 물으면 사진 복사와 메타데이터 저장을 안내합니다. 이후 사용자가 원본 경로를 알려주고 실행을 요청하면, 목적지와 DB 설정을 검증한 뒤 응용 코드를 실행하는 흐름입니다.

Jev는 대화에서 사용자의 의도와 실행할 기능을 판단합니다. Runner는 등록된 기능 설명과 실제 실행 결과를 바탕으로 응답을 구성하고, 응용 어댑터가 사진 복사와 DB 저장 같은 작업을 수행합니다.

Creator의 `jev_creator_manifest.json`에는 적용 위치와 질문이 기록됩니다. Runner에서 사용할 프로젝트에는 서비스가 제공하는 기능과 인자를 담은 `jev_service.json`, 그리고 검증된 인자를 응용 코드에 전달할 실행 어댑터를 별도로 추가하는 구조입니다.
